# 同名怪直接右键设焦点：本轮方案核对

最新进展：用户再次要求查其他插件后，已完成[11套源码动作路径审查](../combat-focus-70888-20261112/OTHER-ADDONS-AUDIT.md)，仍无满足任意同名NPC自动GUID确认的可迁移实现。本机另准备默认关闭的0.1.45[原生缩放/映射鼠标探针](../combat-focus-70888-20261112/SCALE-PROBE.md)，含10秒实验和恢复后5秒同点对照；24个Lua语法、10284项模拟及独立审查通过，尚待实际命中记录。它不设目标/焦点、不代替用户确认，也不是战斗修复。下段“未改插件”为此前只读研究阶段记录。

2026-11-12追加战斗需求研究：本机安装版本已读为70888，其相关六份安全环境/派发源码与下文70862一致，现有逐次GUID自动确认仍不能直接用于战斗。用户已明确“必须由插件自动匹配并确认”，拒绝人工方案；追加属性桥/状态驱动/原生单位框与视觉状态核对也没有补足安全实时身份判定，战斗自动焦点尚未解决，未改插件或实测新候选。详见[70888战斗焦点研究](../combat-focus-70888-20261112/PLAN.md)。下文保留此前研究与脱战阳性，不将旧版原生API阴性直接升格为新构建实测。

2026-11-11；本机客户端 1.60.1 / 70862。需求是直接右键某个怪物格子，将该 GUID 对应的怪物设为焦点，无须先在场景选中；如果内部临时切目标，应恢复原目标且不得误设同名怪。

后续状态（更新至2026-11-12）：用户已接受多次右键。0.1.41独立双点击实际选中两只同名狼，第二只命中冻结GUID；0.1.42[逐次右键流程](GUID-FOCUS-FLOW.md)已有4次原目标为空、3次非空原目标恢复的实际阳性，另外11次中止记录保留。用户授权优化后，本机0.1.43[确认焦点与首步恢复合并候选](FOCUS-OPTIMIZATION-0.1.43.md)已通过模拟/审查，并在实际日志seq16159—16680确认5次非空原目标的组合完成：两次右键准确设B焦点并恢复A，延迟回读一致；另1次恢复未完成中止保留。0.1.43空原目标及完整多步恢复仍待验收，未发布。下列为此前单次输入路线的研究记录，不能据其旧候选状态覆盖本段。

**结果：本轮没有找到满足上述完整需求的新可用实现，问题仍未修通。** 本文研究阶段只新增精确构建接口和同类插件现状记录，没有执行新的游戏操作或发布版本。用户随后指定研究Tab循环，已在本机0.1.40增加默认关闭的[循环入口探针](TAB-CYCLE-TEST.md)，尚未游戏实测；正式点击功能未改，公开版本仍为0.1.37。

## 本轮新增证据

1. [Enemy Frames 当前作者说明](https://www.curseforge.com/wow/addons/enemyframes)已明确提示新更新后点击敌方条选目标失效。其[发布帖](https://www.reddit.com/r/WowUI/comments/1x0vw2v/i_found_a_way_to_make_clickable_enemy_frames_that/)解释，旧实现扩大全部真实姓名板，再把命中区锚到列表条上；作者后续报告新构建使点击失效。后续回复的绝对日期及具体 build 未核实，不能擅自当作官方 70862 改动公告。该来源说明其他作者目前也没有给出可直接沿用的修复。
2. 精确 70862 的 `CanChangeHitTestPoints` / `SetHitTestPoints` / `SetAllHitTestPoints` 与本机旧实验使用的文档相同，不是另一套新机制。命中区仍受姓名板本体边界约束。原生空间命中由 C++ 内部对象负责；普通按钮的 `:Click()` 委托不能据此视为一次真实姓名板空间点击。详见 [命中区核对](NATIVE-HIT-TEST-POLICY-70862.md)。
3. 同样支持 Forever 1.60.1 的 [AKForeverTargeter 最新 0.2.4](https://www.curseforge.com/wow/addons/akforevertargeter/files/9274391)仍说明名称选择无法指定同名单位中的另一只；源码实际按不同名字依次 `/targetexact`，不是 GUID 精确选择器。按名临时选择后比较 GUID，可以拒绝误选，却不能保证命中指定格子。
4. 已查精确构建的目标、单位、姓名板、Gamepad、软目标和地图单位框 API 家族。未找到接受任意 NPC GUID 并写入 target / focus / mouseover 的新公开入口，也未找到创建任意单位别名的接口。这是所列文件的检索结论，不是对客户端全部内部实现的证明。详见 [新 API 家族核对](NEW_API_FAMILY_RESEARCH.md)。

名称宏、循环限制的历史来源、GUID 闸门和原目标恢复的具体分支，另见 [安全宏链研究](SECURE_CYCLE_GUID_RESEARCH.md)。其中列出的最小探针未在本轮建立或执行。

## 方案逐项判断

| 路径 | 可以完成的部分 | 对完整需求的结论 |
| --- | --- | --- |
| 现有 `target`、`focus`、队友目标、`bossN`、`arenaN` 等可操作单位引用 | 其实时 GUID 与格子匹配时可精确绑定；本插件名单已优先这些引用 | 依赖已有引用，不覆盖任意附近怪物 |
| 原始 GUID 直接 focus / GUID 宏 | GUID 能区分身份 | 本机既有有效测试未建立预期焦点，不能交付 |
| `nameplateN` 原生 target / focus | 可读取单位及 GUID | 本机既有有效测试失败；19:44 已观察到 TargetUnit 实际派发仍未选中 |
| 名称选择 → focus → 恢复目标 | 已有名称兼容路径可处理身份可确定的对象 | 名称不编码 GUID，无法保证两只同名怪的指定身份 |
| 名称选择 → GUID 校验 → 仅匹配时 focus → 恢复 | 可作为独立待测的防误设机制 | 只能接受名称解析恰好命中的一只；不能选择任意同名格子，本轮未新增此探针 |
| 同一点击循环 `/targetenemy` 并逐只比较 GUID | 历史开发者资料还提示每宏选敌次数限制 | 当前构建的多次安全斜杠行为未实测，且多次切换破坏 lasttarget 恢复依据；不是可交付方案 |
| 搬移姓名板命中区 / 普通按钮转发原生点击 | 旧 Enemy Frames 曾用搬移方法 | 作者现报失效，精确源码未找到新的转发机制；不重复旧实验 |
| Gamepad / `softenemy` / UnitPositionFrame | 读取或操作引擎已提供的交互、软目标和绘图对象 | 未找到把指定 GUID 变成精确硬目标的新入口 |
