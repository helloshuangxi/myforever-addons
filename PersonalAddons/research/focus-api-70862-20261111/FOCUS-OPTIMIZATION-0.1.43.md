# 0.1.43 本机操作优化

0.1.42已经实际跑通原空及非空敌人恢复。本候选减少一次确认输入：同名怪格子逐次右键寻找，出现“已找到”后，再右键一次会设置焦点并执行第一步恢复。若这一恢复正好返回原目标，流程直接结束；否则继续右键恢复，绝不会再次把后来的目标设为焦点。

## 本机验证步骤

1. `/reload`加载0.1.43，保持脱战，靠近两只同名活怪。
2. 先以原目标为空测试：右键指定格子直到出现“已找到”，下一次右键应同时设置焦点并清空目标。窗口应消失并明确提示完成。`/reload`保存日志。
3. 再以非空原目标测试：先选活怪A，右键另一只同名怪B的格子寻找；命中后确认点击应设置B焦点，并立即尝试恢复A。若尚未回A，继续按“尚未完成”提示右键。结束后检查焦点B、目标A，再重载保存。

与0.1.42相比，通常的“寻找→确认焦点→恢复”三次点击，变成“寻找→确认并恢复”两次；寻找或恢复需要经过多只时仍逐次点击。不是一次点击自动遍历全部敌人，也不需要新宏或新键位。

合并是否实际执行以新日志为准：`action=focus_restore`、`restoreAction`记录恢复类型；逆向Tab另记录`reverse=true`与实际GUID，最终END和READBACK必须同时满足focusMatchesGoal、targetRestored。focus失败、恢复失败、外部焦点或目标变化都保留原来的失败/未完成含义，不能只看黄色焦点框判断结束。

## 回退

第二条命令未执行且当前目标未动时，会自动停用合并，按下一次输入继续独立恢复，保留已经成功的焦点。也可无活跃流程时输入`/mytargets focuscycle staged`切到0.1.42分步方式，`/mytargets focuscycle combined`重新开启合并。这只改变本次会话模式，重载后默认合并；`stop`与`restore`原有入口保留。

没有扩大或移动现有格子、面板和入口；临时提示文字改为清楚的动作和“尚未完成”，使用常规字号。只缓存不变的独立单位列表，每次使用仍按GUID重验；减少重复注册同一可见性驱动，未改变单位判断规则。
