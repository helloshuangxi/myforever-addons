# 0.1.42 同名怪逐次右键焦点流程

用户于2026-11-11明确接受先实现多次右键；同日此前的停止修改要求已经由“那继续完成”和点击方式答复更新。本候选在本机实现，不发布。

## 操作

1. `/reload`加载0.1.42。靠近两只同名活怪，保持脱战。第一次验证请取消当前目标，保留已有焦点可用于检查寻找阶段有没有误改它。
2. 右键你需要的那只怪物的格子。若名称存在歧义，将冻结该格子的GUID，敌方列表在流程中保持位置。
3. 继续右键同一格子，或中央出现的临时按钮。每次点击执行一次原生选敌；“确认焦点”表示已找到指定GUID，下一次右键才设置焦点。
4. 焦点设置后按提示继续右键恢复原目标。原本没有目标会清空；原本选着可验证的独立单位会尝试直接返回；原本选着活敌人时按GUID逐次反向选回。窗口消失并提示完成后，检查焦点黄框，再`/reload`保存日志。

中央按钮左键取消继续寻找并准备恢复原目标；已设置的新焦点不会因取消而清掉。`/mytargets focuscycle status`查看状态，`restore`准备重试恢复，`stop`直接停止。`stop`不会自动改目标，因此未恢复时需要手动选回。重载/离开世界不恢复未完成事务。

每轮寻找最多20次，恢复最多40次；寻找连续三次没有推进也会停止寻找并转恢复。限额不代表已经遍历全部世界单位。原目标死亡、消失、移出可选范围或不在敌对Tab候选集中时，不能保证返回；界面会显示未恢复，不能当作成功。某些友方/死亡NPC没有可验证恢复路径时，开始前直接拒绝，不先改目标。队伍/首领等别名改变身份时会重新核验，绝不把字符串别名当成冻结的原目标。

## 执行边界

- 所有选敌、focus、清目标和返回动作均由真实点击触发原生安全宏。普通Lua只比较GUID、配置下一次点击、显示进度和记录日志；定时器没有目标或焦点动作。
- 寻找期间保留旧焦点；提交前再次核对当前目标正是冻结GUID。焦点提交与恢复各自读回，只有两者都匹配才报告完成。
- 每步核对当前目标仍是上一步自己的结果。人工切换到其他目标或焦点后停止，避免覆盖玩家的新操作。恢复阶段人工选回原GUID时可以确认恢复。
- 战斗和待施法/拖物光标时不准备新的动作；owner格子有安全战斗保护，中央按钮由安全状态驱动隐藏。脱战后需要新的点击。
- 格子姓名和任务身份固定为最初所点GUID，姓名板失效时保留姓名、隐藏不确定血量；中央按钮可在原格子不可操作时继续恢复。
- 友方、敌方玩家与原有无歧义焦点路径继续使用既有处理；Ctrl+右键标记和左键选目标保留。
