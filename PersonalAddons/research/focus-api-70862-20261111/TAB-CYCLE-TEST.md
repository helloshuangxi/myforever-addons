# Tab 循环入口测试：0.1.41 本机候选

用户提出：循环 Tab，每次比对格子 GUID，找到后设焦点，再切回最初目标。GUID 识别本身成立；尚待确认的是同一硬件事件能否多次选择，以及多次选择后如何精确返回最初目标。本候选只测试前一项，没有实现完整焦点功能。

## 使用步骤

1. `/reload` 加载本机 0.1.41。靠近至少两只活怪，保持脱战、视角和位置不动，清空当前目标。敌方第1格需要有活怪名字。
2. 输入 `/mytargets focusprobe cycle 1`，**右键中央蓝色按钮一次**。原生安全宏中连续执行两条 `/targetenemy`，最后 `/cleartarget`。只读 hook 在每条选择接口返回时记录 GUID；宏里没有 `/run`、施法或设置焦点。
3. 保持当前目标为空，输入 `/mytargets focusprobe cyclecontrol 1`。**右键中央蓝色按钮两次**：第一次只执行一条 `/targetenemy`，暂时保留选中的 A；第二次执行一条 `/targetenemy`，记录 B，然后清空测试目标。第一步未确认有效选中时，不准备第二步。若中途手动换成其他目标，第二步拒绝执行。
4. `/reload` 保存日志。需要提前关闭按钮可用 `/mytargets focusprobe off`；若在对照的第一步后中止，当前测试目标仍由玩家自行取消。

`1` 是用于冻结现场参考身份的敌方格号，可以换成有名字的 `1` 至 `20`。探针在准备和首次点击前检查格子绑定及 GUID，拒绝空格、单位换位、非活体敌对 NPC、战斗、待施法光标、携带物品和非空原目标。对照第二步改为检查当前目标仍是第一步记录的 A，允许列表因选中 A 而改用 `target` 单位别名。不会改写永久键位或创建玩家宏。

每次请求测试都会开始一个新的日志 session，续满既有4小时时限；旧事件继续保留在日志环中。准备成功不等于接口已生效。仅在玩家右键测试按钮时选择目标，计时器只读回状态、不补做受保护动作；进入战斗隐藏测试按钮。

0.1.41把开始日志提前到测试请求入口：即使格子为空或其他条件不满足，也记录 `FOCUS_API_PROBE_COMMAND` 和同一requestID的 `FOCUS_API_PROBE_REJECT`，聊天窗口给出中文原因。创建或显示按钮时异常会记具体阶段及错误第一行，停用并隐藏残留框体，要求重载后再准备。没有模块时也会给出提示。如果按钮没有出现，请保留这条中文提示；`/reload`后即可读取本次拒绝日志。此前0.1.40没有这些早期拒绝记录，不能反推本次现场原因。

## 读取结果

- 同一次 `cycle` attempt 有两条 `FOCUS_API_PROBE_CYCLE_STEP`，GUID 都可读且不同：本次同一宏确实选到了两只，说明该入口值得继续验证。最终还须目标为空、焦点未变。
- `cycle` 没有推进，而 `cyclecontrol` 的 A、B 不同：当前现场确实能 Tab 到两只，但双命令宏未在同次点击推进第二只。不能交付成一次右键自动循环。
- 两种测试都没有不同 GUID：不能区分现场候选集不足、接口限制或同步采样不足，应保留“不确定”，不写成成功或确定限制。
- 只有调用次数、`UnitExists=true`、样本缺失/秘密、延迟才出现的目标或模拟通过，均不能当作双选择成功。

日志的 `phase` 区分 `cycle`、`first`、`second`；每次硬件点击有独立 `attemptID`，每次选择接口有 `ordinal`。POST 与0.1秒 READBACK 记录最后目标/焦点，`cycleAdvanced` 和 `controlAdvanced` 仅描述已观测到的 GUID 变化，不代表完整功能通过。

## 完整方案仍欠缺的验证

多次选择 A→B→C 后，`/targetlasttarget` 不能保证返回 A。即使本探针通过，后续也须另外证明“按 GUID 停止并设焦点”以及“恢复原目标，失败保留旧焦点”，覆盖原目标为空、同名、消失和候选集改变等情形。不能把本探针通过写成同名怪右键焦点已修复。

本候选尚未游戏实测。公开版本未更新。
