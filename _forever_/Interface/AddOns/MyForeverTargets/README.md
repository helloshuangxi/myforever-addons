# 我的无限 · 目标选择 0.2.8 本机候选

> 0.2.8 修正脱战普通技能兼容中的死亡保护：明确检查玩家自身，不再因原目标是尸体而提前结束。受术者的存活/关系/身份校验和原目标恢复保留。仅本机候选，尚待游戏复测，未发布。

## 友方施法死亡判断复测

1. 脱战输入 `/reload`，再 `/mytargets log start`。
2. 保留一具怪物尸体作为当前目标，悬停自己或另一名存活友方的格子，按原普通治疗/增益技能键；等技能冷却结束再重复。观察是否对悬停者施放，并保留原目标。
3. 输入 `/mytargets log mark 尸体目标测试成功` 标注实际结果；未成功时把末尾改成“尸体目标测试失败”。也可用活目标、空目标各测一次，分别标注。
4. 输入 `/mytargets log stop`，脱战 `/reload` 或正常退出保存。

`NAME_BRIDGE_PRE/POST`新增版本、配置按键/命令、玩家与原目标死亡读值和读取状态、两者显式死亡宏条件结果，以及代理命令的固定保护是否吻合。日志不包含宏正文，诊断读值不控制施法；继续通过原生技能发送/成功/失败和目标事件核对，前后目标相同本身不证明施法或中途切换成功。此轮只修正已定位的脱战问题，战斗施法仍按既有路径和验证范围。

> 0.2.7 修复单位匹配诊断因单个地址失效而提前结束整轮的问题，默认关闭、仅本机测试，尚未发布。失效日志定位具体测试编号/姓名板地址、触发事件或定时检查、冻结与当前生命周期、移除状态和接口读取状态。选中、焦点、悬停施法的完整问题仍未修复。

单个地址失效后永久退出本次有效匹配，其他地址继续记录。有效集合变化时重新计数，请在新测试组里再各选一次两只怪；复用后的地址不会被当成原怪。可用地址不足两个时仍保留原始比较和失效诊断，但不计为有效双单位匹配。

## 两只同名怪的单位匹配测试

1. 进入副本，脱战 `/reload`，靠近两只同名活怪，让两个原生姓名板同时可见。
2. 清空当前目标（可输入 `/cleartarget`），再输入 `/mytargets unitmatch on`。确认看到带 **0.2.8** 的开启提示，日志会自动记录，不需要测试按钮或新宏。
3. 用游戏原生 Tab 或点击场景先选中第一只，停一秒；再选中另一只，停一秒。查看聊天里的匹配汇总。测试编号表示开启时固定的姓名板地址，不是重排后的格子序号；程序不读取名字来判断同名。
4. 输入 `/mytargets unitmatch off`，再 `/reload` 保存。off会结束本测试拥有的同一日志会话；如果其他模块已开启新会话，不会停止别人的日志。

测试器记录“允许比较”“结果是否受限”“是否同一单位”的各自公开性与布尔值。`false`、nil、受限、异常、接口缺失分别保存，不把未知结果当不匹配。只有当前组至少两个有效地址、恰好一个公开匹配且其他有效地址均公开不匹配时才计入观察；两个地址分别得到这样的结果后会给出汇总，仍需实际日志复核。失效地址的原始比较仍可记录，但不会算作原怪的有效匹配。

它不会自动切目标、设焦点、施法或修改原键位／玩家宏。进战、换地图、180秒或40个完成样本后自动结束；单个姓名板消失／重加不再直接关闭整轮。`/mytargets unitmatch sample` 可补采当前选择，`status` 查看状态。

原来的 `/mytargets instanceactions on` 为另一个试验，不要同时开启。0.2.5实测已确认其原生标记能分别作用于两只同名怪，直接姓名板选中和焦点失败；本次不改变这套动作或既有友方施法。

以下保留0.2.5及更早功能的范围说明。

> 0.2.5 增加默认关闭的副本原生操作试验，尚未证明客户端接受这些动作。没有启动游戏或发布；官网与软件客户端公开版本仍为0.2.2。完整战斗操作方案仍未解决。

副本中脱战、敌人格子有名字时，输入 `/mytargets instanceactions on`。试验在原有格子上提供左键选中、右键焦点、Ctrl＋右键打开1—8号标记，以及悬停按原普通敌方技能键的原生入口。每格固定原生姓名板地址，不按同名怪的名字猜测，不切目标再切回；覆盖期间显示跟随同一地址，原有安全格子不重新准备其他身份。

此命令自动开启一轮本机日志。先测试左键、焦点与标记，再测试一次普通攻击技能键；**进入战斗即自动停止本试验**，不能据此认为持续战斗操作已实现。原生单位操作或施法条件被拒绝会记录拒绝或未知，不回退攻击当前目标。技能仅接已发现的普通伤害技能，宏、物品和其他插件占用的按键不转换。

完成后输入 `/mytargets instanceactions off`、`/mytargets log stop`、`/reload` 保存。也可点击敌方面板旁的“停止”；该停止按钮立即归还临时按键，脱战后清理引用。更改布局、键位或切地图也会结束试验。`/reload` 后保持默认关闭。日志分别记录准备、悬停、点击前、原生接口调用、点击后和延迟读回；调用发生不算成功，对施法仍保留 recipientProven=false。

离线语法、模拟与原格子集成检查已通过；这些检查不能代替游戏原生动作验收。关闭试验时继续使用以下0.2.4已验收的显示路径，友方既有控制器未改动。

## 安装与更新

完整退出游戏，把整个 `MyForeverTargets` 文件夹放入 `_forever_/Interface/AddOns/`，保留 WTF 与原有 SavedVariables，再启动游戏。包内包含所需第三方库；不要多套一层同名目录。我的无限插件管理器 0.2.1 及以上支持安装和更新目标选择；旧管理器须先从官网下载新版程序。

更新保留已有位置、面板开关和设置。脱战拖动标题栏或独立图标可保存位置；`/mytargets reset` 恢复面板和图标位置，并打开两侧。

## 面板与点击

友方分团队 20 格、小队 5 格、附近 5／10／20 格；敌方单列表可选 5／10／20 格。附近名单按可用距离信息排序，未知距离放后面；悬停时暂缓所在名单重排，战斗中冻结布局。名单受客户端可见与可读单位范围限制。

- 主格 76×58，间距 1 像素，显示职业色姓名、整格血量和底部资源条。敌人下方使用 76×26 小目标条，显示其目标的姓名、职业与血量。
- 可操作的公开身份格子：左键选择当前目标，右键设置焦点，Ctrl＋右键打开标记菜单。重复点击不取消目标或焦点。目标用红框、焦点用黄框提示；标记受游戏单位与队伍权限限制。副本受限身份格子使用上方单独试验，原生动作尚待验证。
- 两侧各有“×”关闭按钮。屏幕左侧玉绿色“目”字图标可打开面板菜单，右键快速开关两侧；战斗中的开关与布局变更等脱战后应用。
- 显示本人（含宠物、载具）施加的限时 buff／debuff；友方还显示本人可驱散的 debuff。隐藏常驻光环和采集追踪，每类一排，更多效果用滚轮查看。敌人的小目标条不显示效果图标。
- 操作说明放在浮层。悬停与焦点头顶动画只附着于可见姓名板，不猜测屏幕外单位位置；当前目标不另加头顶动画。

## 普通技能悬停兼容

两侧“施法”按钮控制同一个开关，也可输入 `/mytargets legacycast on` 或 `off`。只接普通技能：友方治疗／增益、敌方伤害；按下或松开沿用原动作条设置。已有玩家宏、物品、鼠标按键技能和其他插件占用的键保持原路径，不创建或改写玩家宏、永久键位。

脱战时，悬停格子按原技能键，通过临时选中该单位施法，再恢复原目标；原先无目标则恢复为空。这会改变上一目标历史。附近友方的脱战治疗／增益与原目标恢复已有此前用户实测。

战斗时，自己、小队／团队等固定单位格使用战前准备的直接单位施法，不切当前目标；附近友方玩家主格使用战前核验的原生完整姓名，短暂选中、施法并恢复原目标。内部空格和姓氏按客户端原样保留，不手工拼接服务器名；若没有可信完整姓名则保留旧条件。敌方主格继续使用既有战前准备路径。新出现、失效或身份不匹配的格子不会绕过保护层；没有战前准备的格子不能临时补上战斗动作。

在本机 1.60.1 build 70938 的“智慧祝福（等级 1）”场景，19 次玩家姓名路径均选中指定玩家并恢复原敌人目标；4 次技能发送事件的对象全名匹配该玩家，其中 3 次有同一施法编号的成功事件，1 次失败并伴随冷却。**该证据不等于已确认增益实际附加**；原先无目标、原目标为友方、选择失败或其他技能尚未完整实测。

名称方式不能仅靠 GUID 精确施放同名怪物；无法确认名称唯一或单位身份时拒绝准备。技能仍受距离、视线、朝向、冷却与游戏规则限制。**本版不是任意格子的原生 `@mouseover` 修复；敌人的小目标条不新增战斗施法支持。**

## 焦点

附近名称兼容焦点需要脱战。同名怪可按提示多次右键：每次真实点击推进一次选敌，插件按冻结 GUID 匹配，找到后准备焦点确认，再恢复原目标；看到“尚未完成”应继续按提示操作，直到流程完成。默认合并确认焦点与首步恢复，`/mytargets focuscycle staged` 可改用分步模式，`combined` 返回合并模式。

战斗中任意怪物按 GUID 自动匹配并设置焦点仍未解决。已有脱战焦点、同名怪匹配与目标恢复的验证范围不扩大为战斗焦点保证。相关边界见 `VALIDATION.md`。

## 排查与验证范围

需要排查时输入 `/mytargets log start`，复现后输入 `/mytargets log stop`，再 `/reload` 保存。日志记录格子身份、输入保护、按键接管、施法事件和前后目标读回；不记录聊天或玩家宏正文。记录最多 4 小时／5000 条，到限后需重新开始。

日志只保存在本机，不包含于下载包。按键已接管、目标恢复或观察窗内出现施法事件，都不能单独证明对正确的人成功施法。具体验证与未完成项见包内 `VALIDATION.md`；第三方来源与许可见 `Libs/SOURCES.md`。
