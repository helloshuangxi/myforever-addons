# UX-002 优秀游戏界面的做法，以及插件学了哪些

日期：2026-11-14。分支 `feature/ux-001-unified-style`。不改版本号，不发布。

## 参考了什么

| 来源 | 讲了什么 | 对我们的意义 |
| --- | --- | --- |
| Celia Hodent《The Gamer's Brain》，Epic/Fortnite 用户体验负责人 | 信息放在视线和注意力所在的位置，不要让玩家去屏幕角落找；“形式服从功能”；“信号与反馈”：信号邀请玩家行动，反馈确认行动并教会下一次 | 操作结果应出现在刚点的面板旁边，不能只写进聊天框 |
| 魔兽 Dragonflight 界面重做（暴雪官方） | 从底层重做，目标是不杂乱的布局；编辑模式可移动几乎所有元素并吸附网格；布局可命名、保存、分享，并跟随专精切换；选项菜单加了搜索 | 我们的面板保持统一外观和可预期的位置；后续可做网格吸附与布局方案 |
| FFXIV HUD Layout（官方指南） | 每个元素可单独调大小、透明度；可以把目标信息拆开放；多套布局可复制 | 支持“只显示需要的那块”，与目标面板的敌我分区一致 |
| ElvUI、Plater、DDingUI 等知名插件 | 半透明深色底、低调边框；所有框体共用一套设计语言 | 与 UX-001 的 Midnight 统一样式一致 |
| HUD 设计综述（York 大学实验、行业文章） | HUD 越少越好；血量类关键信息用 HUD 最快；最小化 HUD 只在需要时出现；不能只靠颜色，要照顾色弱 | 战斗中只保留关键状态；颜色只做第二提示 |

## 落到插件上的改动

1. **反馈出现在视线所在处**
   - 共享样式新增 `MyForeverStyle.Toast(anchor, text, kind)`，版本号升为 3。
   - 提示紧贴刚使用的面板上方，约 2.6 秒后淡出。面板不可见时显示在屏幕上方。
   - 它是普通非安全框体，挂在 UIParent 上，战斗中显示也安全。
   - 左侧色条只是第二提示，意思完全靠文字。
2. **目标选择：用一对“信号与反馈”消除战斗中的不确定**
   - 新增 `NS.Notify`：完整说明照旧写进聊天框留底，同时在可见的敌方面板旁显示短提示。敌方面板不可见时依次退到友方面板、启动图标。
   - 战斗中改设置时提示“已记住，脱战后应用”。脱战真正应用时再提示“设置已应用”。
   - 以下操作也使用同样的提示：悬停施法、附近识别、重置位置。
   - 只改了提示，没有碰任何安全框体、绑定或友方施法路径。
3. **玩家行为面板**：战斗中拒绝导出或拒绝新会话时，原因直接显示在面板旁。
4. **测试**：新增 `style_toast_test.lua`，共 16 项检查，覆盖以下几点：
   - 锚点选择与回退；
   - 先保持后淡出，最后自动隐藏；
   - 重复使用同一个提示框；
   - 没有样式模块或提示本身出错时，调用者不受影响。

   全部 70 个模拟测试通过。

## 考虑过但这次没有做

- **闲置自动变淡**（Metro、Destiny 风格的情境 HUD）：目标面板需要随时能看到、能指向。导航 HUD 的 0.56/0.12 透明度是作者确认过的，所以默认不改。以后可以做成可选开关。
- **Esc 关闭随身手册和玩家行为面板**：这两个面板用自己的 `shown` 记住开关状态。Esc 只会隐藏面板，不会写回这个状态，重载后面板又会出现，行为反而不一致。要做的话，需要先把关闭统一走一个入口。
- **编辑模式式的网格吸附、布局方案、按专精切换布局**：价值高，但牵涉每个插件的位置存储。这一项列为下一步的候选。

## 未验证

- 没有在游戏里实际看过提示条，只有离线模拟测试。
- 中文字体下 `GetStringWidth` 的实际宽度、DIALOG 层级在过场动画中的表现，都需要实机确认。

## 第二步：统一布局（学 Dragonflight 编辑模式，再加上现代编辑器的交互）

作者反馈：魔兽自带的编辑模式有点旧，要融入其他游戏和工具更先进的交互。

### 借鉴了什么

| 来源 | 借鉴 |
| --- | --- |
| Figma、Keynote、Illustrator 的智能参考线 | 拖动时与其他元素的边缘或中心对齐，就出现参考线，并在吸附距离内自动贴上 |
| Dockview 等编辑器 | 按住修饰键暂停吸附，自由放置 |
| COD Mobile、FFXIV HUD 编辑器 | 一个界面里看到所有元素；元素各自可调 |
| 魔兽 Dragonflight 编辑模式 | 网格对齐；战斗中不能编辑 |

### 做了什么（共享样式 v4）

- **拖动任何“我的无限”面板时，屏幕上淡淡显示网格。**
  - 网格从屏幕中心起画，每 32 单位一条线；中线更亮。
  - 顶部提示：“对齐边缘或网格 · 按住 Alt 自由放置 · /myui 摆放全部面板”。
- **智能参考线与磁吸。**
  - 比较的对象：被拖面板的左边、右边、中线，与其他已打开面板的边缘和中线，以及屏幕中心。
  - 相差 8 单位以内时，出现绿色参考线；松手后贴齐。
  - 没有可贴的参考线时，吸附到 8 单位网格。
- **按住 Alt 松手**：完全不吸附，面板留在松手的位置。
- **`/myui`（或 `/mylayout`）布局模式**，界面上有：
  - 网格；
  - 每个打开的面板外面有蓝色描边和名字标签；
  - 顶部布局条：说明怎么操作，列出“未打开”的面板，一个“完成”按钮。
- **战斗安全。**
  - 战斗中不能进入布局模式；进入战斗会自动退出。
  - 战斗中不碰受保护的框体。
  - 目标选择拖的是它原有的非安全替身框。吸附只作用在替身上，并且只在脱战时。
- **影响范围。**
  - 各插件原有的拖动把手、锁定和位置保存全部保留。
  - 每个插件只在“开始拖动”和“松手后、保存前”各加一行调用。
  - 接入的面板：
    - 世界向导：指引、任务目标、图标；
    - 商业技能：主面板、图标、采集提示；
    - 目标选择：友方、敌方、图标；
    - 微信式聊天：窗口、图标；
    - 玩家行为；
    - 随身手册；
    - 宏助手。
- **顺带修复。** 共享 `call` 工具原先最多只返回 3 个值，导致 `GetPoint` 拿不到 x、y。现在会原样返回全部值。
- **测试。**
  - 新增 `style_layout_test.lua`，共 29 项检查，覆盖：
    - 网格；
    - 缩放换算；
    - 边缘与中心磁吸；
    - 隐藏面板不参与；
    - 替身排除；
    - Alt；
    - 战斗；
    - 布局模式开关与未打开列表。
  - 两个原有测试检查精确保存坐标，改为在“按住 Alt”下拖动，测试目的不变。
  - 全部 71 个测试通过。
  - 预览图：`docs/ux-001/layout-mode.png`，是布局模拟，不是游戏截图。

### 第三步：布局升级（2026-11-14）

在布局模式里加上了现代编辑器常见的操作：

- **选中面板**：点面板上方的名字标签，或者直接拖动它。选中后边框和标签变成绿色，标签末尾显示“（已选）”。
- **方向键微调**：方向键每次移动 1 单位，按住 Shift 每次移动 8 单位。
  - 只有方向键、Ctrl+Z、Esc 会被布局模式占用，其他按键照常交给游戏。
- **撤销**：布局条上的“撤销”按钮或 Ctrl+Z，最多记住 30 步。
  - 拖动、还原都各算一步；连续的方向键微调合并成一步。
  - 撤销后的位置会写回各插件自己的存档。
- **还原默认位置**：只对选中的那个面板生效，用的是插件原有的默认值。还原本身也可以撤销。
- **调整大小**：只在插件本来就有缩放设置的面板上出现。
  - 目标选择：70%–140%，走原有的 `NS.SetScale`；
  - 商业技能主面板：65%–160%，走原有的 `ns.SetScale`；
  - 采集提示：70%–130%。
- **Esc 退出**布局模式。战斗中不能微调、不能撤销，也进不了布局模式。

**各插件接入情况**

- **全部支持**（保存、还原、撤销、微调）：
  - 世界向导：指引、图标；
  - 商业技能：主面板、图标、采集提示；
  - 目标选择：友方、敌方、图标；
  - 微信式聊天：窗口、图标；
  - 随身手册。
- **只在本次登录内移动**：世界向导的任务目标、玩家行为、宏助手。这三个面板原来就不保存位置，所以没有“还原”，微调和撤销只在本次登录内有效。
- **目标选择友方、敌方面板**：
  - 保存时用原有的左上角换算 `topLeftPosition`；
  - 还原时用 `NormalizeDB` 的默认值，并且只还原所选的那一个面板。
- 采集提示的保存逻辑提成了 `savePlacement()`，拖动和布局模式共用这一份。

**测试**：`style_layout_test.lua` 增加到 54 项检查，新增覆盖：
- 拖动时记录历史并选中面板；
- 方向键微调、Shift 步长、连续微调合并为一步；
- 按键放行；
- Ctrl+Z 两级撤销，并写回存档；
- 还原及撤销还原；
- 大小加减到上下限；
- 没有回调的面板；
- Esc 退出；
- 战斗中拒绝操作。

全部 71 个测试通过。预览图：`docs/ux-001/layout-mode-selected.png`。

### 还没做

- 在布局模式里调不透明度：各插件的背景透明度目前写在各自代码里，需要先统一。
- 多套布局方案、按专精切换：需要一个“我的无限”共用的存档位置。
- 实机验证：特别是 `SetPropagateKeyboardInput` 的按键放行、中文字体下名字标签的宽度。
