# UX-002 优秀游戏界面的做法，以及插件学了哪些

日期：2026-11-14。分支 `feature/ux-001-unified-style`。不改版本号，不发布。

## 参考了什么

| 来源 | 讲了什么 | 对我们的意义 |
| --- | --- | --- |
| Celia Hodent《The Gamer's Brain》，Epic/Fortnite 用户体验负责人 | 信息放在视线和注意力所在的位置，不要让玩家去屏幕角落找；“形式服从功能”；“信号与反馈”：信号邀请玩家行动，反馈确认行动并教会下一次 | 操作结果应出现在刚点的面板旁边，不能只写进聊天框 |
| 魔兽 Dragonflight 界面重做（暴雪官方） | 从底层重做，目标是不杂乱的布局；编辑模式可移动几乎所有元素并吸附网格；布局可命名、保存、分享，并跟随专精切换；选项菜单加了搜索 | 我们的面板保持统一外观和可预期的位置；后续可做网格吸附与布局方案 |
| FFXIV HUD Layout（官方指南） | 每个元素可单独调大小、透明度；可以把目标信息拆开放；多套布局可复制 | 支持“只显示需要的那块”，与目标面板的敌我分区一致 |
| ElvUI、Plater、DDingUI 等知名插件 | 半透明深色底、低调边框；所有框体共用一套设计语言 | 与 UX-001 的 Midnight 统一样式一致 |
| HUD 设计综述（York 大学实验、行业文章） | HUD 越少越好；血量类关键信息用 HUD 最快；最小化 HUD 只在需要时出现；不能只靠颜色，要照顾色弱 | 战斗中只保留关键状态；颜色只做第二提示 |

## 落到插件上的改动

1. **反馈出现在视线所在处**
   - 共享样式新增 `MyForeverStyle.Toast(anchor, text, kind)`，版本号升为 3。
   - 提示紧贴刚使用的面板上方，约 2.6 秒后淡出。面板不可见时显示在屏幕上方。
   - 它是普通非安全框体，挂在 UIParent 上，战斗中显示也安全。
   - 左侧色条只是第二提示，意思完全靠文字。
2. **目标选择：用一对“信号与反馈”消除战斗中的不确定**
   - 新增 `NS.Notify`：完整说明照旧写进聊天框留底，同时在可见的敌方面板旁显示短提示。敌方面板不可见时依次退到友方面板、启动图标。
   - 战斗中改设置时提示“已记住，脱战后应用”。脱战真正应用时再提示“设置已应用”。
   - 以下操作也使用同样的提示：悬停施法、附近识别、重置位置。
   - 只改了提示，没有碰任何安全框体、绑定或友方施法路径。
3. **玩家行为面板**：战斗中拒绝导出或拒绝新会话时，原因直接显示在面板旁。
4. **测试**：新增 `style_toast_test.lua`，共 16 项检查，覆盖以下几点：
   - 锚点选择与回退；
   - 先保持后淡出，最后自动隐藏；
   - 重复使用同一个提示框；
   - 没有样式模块或提示本身出错时，调用者不受影响。

   全部 70 个模拟测试通过。

## 考虑过但这次没有做

- **闲置自动变淡**（Metro、Destiny 风格的情境 HUD）：目标面板需要随时能看到、能指向。导航 HUD 的 0.56/0.12 透明度是作者确认过的，所以默认不改。以后可以做成可选开关。
- **Esc 关闭随身手册和玩家行为面板**：这两个面板用自己的 `shown` 记住开关状态。Esc 只会隐藏面板，不会写回这个状态，重载后面板又会出现，行为反而不一致。要做的话，需要先把关闭统一走一个入口。
- **编辑模式式的网格吸附、布局方案、按专精切换布局**：价值高，但牵涉每个插件的位置存储。这一项列为下一步的候选。

## 未验证

- 没有在游戏里实际看过提示条，只有离线模拟测试。
- 中文字体下 `GetStringWidth` 的实际宽度、DIALOG 层级在过场动画中的表现，都需要实机确认。
